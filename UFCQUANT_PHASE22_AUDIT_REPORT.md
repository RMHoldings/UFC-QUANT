# UFCQuant Web Phase 22 — Audit Report

**Audit date:** 2026-11-07  
**Audited artifact:** `ufcquant_web_mvp_phase22.zip` (source extracted to working tree)  
**Verdict:** **NOT PRODUCTION READY**  
**Scope note:** This audit combines source/configuration inspection, local API tests, SQLite integrity validation, and current official-source verification. A deployed Netlify URL and Render URL were not supplied. Browser automation was attempted against local loopback/static-host URLs with Playwright + Chromium, but the browser environment rejected navigation (`ERR_BLOCKED_BY_ADMINISTRATOR`). Therefore, no claim is made that the deployed app was browser-tested. The deployed backend's behavior, live upstream ingestion and network performance remain unverified.

## Executive summary

Phase 22 is a small static dashboard + FastAPI adapter around existing UFCQuant research/CLI modules. It has a health indicator, button to fetch an upcoming card from UFC.com, and a button to open a clearly labeled synthetic/demo report. It does **not** implement the comprehensive fighter profile, matchup analysis, forecast probability, prediction report, CSV ingestion, report download workflow or persistence/scheduler features specified in the audit request.

The supplied test suite initially passed **43 tests**. Two reproducible schema-validation gaps were fixed in `ufc_quant/api.py`: the API previously accepted an event field that was not an object and fight rows that were not objects, even though these malformed payloads could break frontend rendering. Two regression tests were added. Final test result: **45 passed**.

SQLite `PRAGMA integrity_check` returned `ok`; the bundled database contains a `predictions` table. This does not establish durable production persistence; the deployment notes explicitly state that persistent database deployment and scheduler are not configured.

## Bugs reproduced and fixed

### BUG-API-001 — Invalid event schema accepted as live card
- **Severity:** Medium
- **Root cause:** `upcoming_event()` checked that card was a dictionary and `fights` was a list but did not validate `event` type.
- **Fix:** Require `event` to be a dictionary.
- **Regression test:** `test_upcoming_event_endpoint_rejects_invalid_event_schema`.

### BUG-API-002 — Non-object fight rows accepted by API
- **Severity:** Medium
- **Root cause:** Fight rows were returned unchecked. A `null` row could throw in the frontend card renderer when accessing fighter properties.
- **Fix:** Require each fight row to be a dictionary; otherwise map upstream malformed data to a controlled 502 response.
- **Regression test:** `test_upcoming_event_endpoint_rejects_non_object_fight_rows`.

## Limitations and remaining work

1. Provide the actual Netlify site URL and Render API URL to complete deployed browser/network QA.
2. The web MVP currently has no fighter profiles, fighter stats display, matchup analysis, forecast generation, probability calibration, real prediction history, CSV import or explicit report download feature.
3. Verify source adapter against real UFC.com event/card payload in a network-enabled environment; parsing may be affected by upstream HTML changes or bot restrictions.
4. Confirm UFCStats historical fighter-stat data integration and identity matching before surfacing statistics.
5. Establish real temporal walk-forward evaluation on curated historical data, reporting sample size, test window, Brier, log loss, ROC-AUC, calibration error and baseline/skill score. No metrics should be exposed until measured.
6. Configure exact Netlify origin in Render CORS and remove placeholder configuration.
7. Add persistent database storage and a scheduler if production requirements call for stored forecasts and scheduled ingestion.
8. Run browser console/network, mobile responsive, endpoint latency, memory and dependency-security scans in a permissive CI/browser environment.

## Final verdict

**NOT PRODUCTION READY.** The currently supplied Phase 22 web MVP is a useful operational dashboard prototype for health checks, source-dependent upcoming-card fetching, and synthetic demo report rendering. The test suite passes with two new schema guardrails, but core product requirements for verified fighter statistics and real, calibrated fight predictions are not implemented in this web application. Deployed browser validation and model validation remain outstanding.
